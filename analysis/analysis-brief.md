## 0. Executive Summary

BrokenLinkBrief (BLB) has per-project `ProjectStore.summarize()` and a per-scan
dashboard, but no **portfolio-level aggregation**: an agency managing many saved
projects cannot see a cross-project health overview in one place. This brief specs
a **Python-native portfolio aggregation API** (`GET /api/portfolio` and
`GET /api/portfolio/summary`) plus a **portfolio view embedded in the existing
stdlib dashboard**, reusing the already-shipped `ProjectStore`, `ScanHistoryStore`
and `findings.FindingStore` data models. No new runtime dependencies.

### 1.2 The existing `summarize()` — per-project aggregation

`ProjectStore.summarize(project, history_store)` — `src/brokenlinkbrief/projects.py:200-229`:

```python
def summarize(self, project: Project, history_store: object) -> dict[str, object]:
    """Aggregate the latest retained scan for every project target."""
    scanned_targets = 0
    total_links = 0
    broken_count = 0
    last_scan_timestamp: str | None = None
    for target in project.targets:
        records = history_store.get_history(target, limit=1)
        if not records:
            continue
        scanned_targets += 1
        record = records[0]
        timestamp = record.get("timestamp")
        if timestamp and (last_scan_timestamp is None or timestamp > last_scan_timestamp):
            last_scan_timestamp = timestamp
        results = record.get("results", [])
        total_links += len(results)
        broken_count += sum(
            1
            for item in results
            if (item.get("status") is not None and item.get("status") >= 400)
            or (item.get("status") is None and item.get("reason") is not None)
        )
    return {
        "scanned_targets": scanned_targets,
        "unscanned_targets": len(project.targets) - scanned_targets,
        "total_links": total_links,
        "broken_count": broken_count,
        "last_scan_timestamp": last_scan_timestamp,
    }
```

Facts and limitations:
- Consumes the **JSONL `HistoryStore`** (per-URL history), *not* the SQLite
  `ScanHistoryStore` (per-project scan records). Two parallel history systems
  exist; `summarize()` is coupled to the JSONL one.
- Reads **every JSONL file on disk per call** (`HistoryStore.get_history` globs
  `.history/*.jsonl` and filters by URL — `package.py:450-477`). For a portfolio
  of N projects × M targets this is O(N×M) full-directory scans → quadratic
  blowup at portfolio scale. **The aggregation API must NOT call
  `summarize()` per project naively** (see §3).
- "Broken" definition (shared everywhere): `status >= 400`, or `status is None
  and reason is not None`. Reuse the same predicate for portfolio metrics so
  numbers reconcile with per-project views.
- No "fixed"/health-score concept; `summarize()` output keys:
  `scanned_targets, unscanned_targets, total_links, broken_count, last_scan_timestamp`.

Consumers of `summarize()` today:
- `app.py:1338-1342` — `GET /api/projects` embeds `scan_summary` into each
  project payload via `store.summarize(item, history_store)`.
- `tests/test_projects.py`, `tests/test_dashboard_batch_workflow.py` exercise it.

## 2. Clustered Options — Aggregation Strategies

### Option A: Naive portfolio loop over `summarize()` (rejected)

```
for project in store.list_active():
    row = store.summarize(project, HistoryStore())   # O(full JSONL dir) each
```
- Pro: zero new code.
- Con: O(N×M) full-directory JSONL scans per request; reads every file on every
  call; no trend data; cannot produce "fixed" metric; **does not scale past a
  handful of projects**. Violates the research finding that the actionable
  portfolio overview must reconcile to per-project totals.

### Option B: SQLite-first aggregation via `ScanHistoryStore` (chosen)

Read the **`scan_history` SQL table** once with a single indexed query
(`WHERE project_id IN (...)`, `ORDER BY scan_timestamp DESC`), take the latest
record per project, and aggregate in Python. Optionally join
`project_findings` for resolved counts.

- Pro: one query, no JSONL globbing; `scan_history` already has
  `total_links`/`broken_count`/`new_broken_count`/`status` per project scan;
  same DB file as projects (`configured_project_db()`); fast trend queries
  (`scan_timestamp` filter); reconciles to per-project scan records.
- Con: relies on project scans being recorded via `ScanHistoryStore.record_scan`
  (scheduled scans + jobs do; ad-hoc dashboard scans of raw URLs do not — those
  stay in JSONL). Acceptable: portfolio is project-scoped by definition.

### Option C: Hybrid — SQLite latest + JSONL last-timestamp fallback (stretch)

Use `ScanHistoryStore` as primary; for projects with no SQLite record, fall back
to one `summarize()` call (single JSONL pass, cached).
- Pro: covers straggler projects; completeness.
- Con: reintroduces per-project JSONL reads in the fallback path; caching adds
  complexity. **Defer to P2**; do not build in P0.

### Chosen: **Option B**, with the exact SQL in §4.1. Fallback option C recorded as
a P2 candidate (t_72053d3c execution note).

```python
# src/brokenlinkbrief/portfolio.py
"""Portfolio-level aggregation for the multi-site dashboard."""
from __future__ import annotations
from dataclasses import dataclass, asdict
from typing import Any

@dataclass(frozen=True)
class PortfolioProjectRow:
    """One project's aggregated row in the portfolio view."""
    project_id: str
    project_name: str
    total_links: int
    broken_count: int
    new_broken_count: int
    open_findings: int
    resolved_findings: int
    last_scan_timestamp: str | None
    last_scan_status: str            # "completed" | "failed" | "never_run"
    pinned: bool
    archived: bool

@dataclass(frozen=True)
class PortfolioSummary:
    """Cross-project totals."""
    projects: int                    # active projects counted
    scanned_projects: int
    unscanned_projects: int
    total_links: int
    broken_count: int
    new_broken_count: int
    open_findings: int
    resolved_findings: int
    health_score: float              # 0.0-100.0, see formula below
    last_scan_timestamp: str | None

@dataclass(frozen=True)
class PortfolioTrendPoint:
    """One day of aggregated broken-link trend across selected projects."""
    date: str                        # "YYYY-MM-DD"
    total_links: int
    broken_count: int

def _is_broken(item: dict[str, Any]) -> bool:
    """Shared broken predicate: status >= 400, or status None with reason set."""
    status = item.get("status")
    return (status is not None and status >= 400) or (
        status is None and item.get("reason") is not None
    )

def get_portfolio(
    project_ids: list[str] | None = None,
    *,
    project_store: ProjectStore | None = None,
    history_db: sqlite3.Connection | None = None,
    finding_store: FindingStore | None = None,
) -> PortfolioSummary:
    """Aggregate latest per-project scan records into a portfolio summary.

    project_ids=None → all ACTIVE projects. Archived projects are excluded
    unless explicitly listed in project_ids.
    Returns PortfolioSummary (never raises on empty data).
    """

def get_portfolio_rows(
    project_ids: list[str] | None = None,
    *,
    project_store: ProjectStore | None = None,
    history_db: sqlite3.Connection | None = None,
    finding_store: FindingStore | None = None,
) -> list[PortfolioProjectRow]:
    """Per-project rows for the dashboard; same filtering rules as get_portfolio."""

def get_portfolio_trends(
    project_ids: list[str] | None = None,
    days: int = 30,
    *,
    project_store: ProjectStore | None = None,
    history_db: sqlite3.Connection | None = None,
) -> list[PortfolioTrendPoint]:
    """Daily broken-link trend across selected projects for the last `days` days.

    days <= 0 → all history. Returns ascending list of {date, total_links,
    broken_count}; days with no records are omitted (chart fills gaps).
    """
```

**Exact SQL (latest scan per project):**

```sql
SELECT sh.* FROM scan_history sh
JOIN (
    SELECT project_id, MAX(scan_timestamp) AS max_ts
    FROM scan_history
    WHERE project_id IN (?, ?, ...)      -- or all: omit WHERE
    GROUP BY project_id
) latest ON latest.project_id = sh.project_id
         AND latest.max_ts = sh.scan_timestamp
```

Health score formula: `round(100 * (1 - broken_count / total_links), 1)` when
`total_links > 0`, else `100.0` (all-empty portfolio). Document in README.

**HTTP routes (exact):**

| Route | Params | Response |
|---|---|---|
| `GET /api/portfolio` | `project_ids` (comma-separated, optional), `token`/Bearer | `200` → `{"summary": {...PortfolioSummary}, "projects": [ {...PortfolioProjectRow} ]}`; `401` on bad token; `400` on malformed project_ids |
| `GET /api/portfolio/summary` | `days` (int, default 30, `<=0` = all), `project_ids`, `token`/Bearer | `200` → `{"summary": {...}, "trend": [ {...PortfolioTrendPoint} ]}`; same error codes |

Route wiring in `app.py` (place before the `/api/scheduled-projects` block or
right after DASHBOARD ENDPOINTS):

```python
# PORTFOLIO ENDPOINTS
if path == "/api/portfolio" or path == "/api/portfolio/summary":
    expected_token = get_configured_scan_token()
    ...  # identical auth gate as /api/dashboard/* (token param or Bearer)
    project_store = ProjectStore()
    history_db = sqlite3.connect(project_store.path)   # reuse the same DB file
    history_db.row_factory = sqlite3.Row
    try:
        if path == "/api/portfolio":
            rows = get_portfolio_rows(project_ids=parsed_ids, project_store=project_store,
                                      history_db=history_db, finding_store=FindingStore())
            summary = get_portfolio(project_ids=parsed_ids, project_store=project_store,
                                    history_db=history_db, finding_store=FindingStore())
            _write_json(self, 200, {"summary": asdict(summary),
                                    "projects": [asdict(r) for r in rows]})
        else:  # /api/portfolio/summary
            summary = get_portfolio(...)
            trend = get_portfolio_trends(project_ids=parsed_ids, days=days, ...)
            _write_json(self, 200, {"summary": asdict(summary), "trend": [asdict(p) for p in trend]})
    finally:
        history_db.close()
```
